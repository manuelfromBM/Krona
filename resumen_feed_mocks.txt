CLIENTE HTTP YA EXISTENTE (listo para usar):
- apps/web/src/lib/api-client.ts
  - Expone `apiClient.get<T>(path)` y `apiClient.post<T>(path, data)`.
  - Usa como base `process.env.NEXT_PUBLIC_API_URL` (hay que verificar que
    apps/web/.env.local tenga `NEXT_PUBLIC_API_URL=http://localhost:3001`).
  - Lanza `ApiError` si la respuesta no es ok.

ENDPOINT REAL EN EL BACKEND:
- GET /feed -> apps/backend/src/modules/feed/presentation/feed.controller.ts (líneas ~60-64)
  Devuelve: { posts: [...], nextCursor }
  Cada post (función toFeedResponse) tiene esta forma:
    {
      id,
      user: { id, username, initials },
      media: { type, urls, duration },
      likes,
      likedByMe,
      caption,
      commentsCount,
      createdAt
    }
- Otros endpoints relevantes del mismo controller:
  - POST   /feed/posts                  -> crear post
  - POST   /feed/posts/:id/like         -> like
  - DELETE /feed/posts/:id/like         -> unlike
  - GET    /feed/posts/:id/comments     -> listar comentarios (NO vienen embebidos en el feed)
  - POST   /feed/posts/:id/comments     -> crear comentario

DESAJUSTE DE TIPOS IMPORTANTE (pendiente de resolver cuando se conecte):
El tipo `Post` del frontend (usado en mockPosts.ts) tiene campos que el backend
NO devuelve en toFeedResponse:
  - user.verified
  - user.isFollowing
  - user.avatar
  - likedBy
  - comments (array embebido)
  - isSuggestion
Habrá que decidir entre:
  (a) crear un adapter/mapper que traduzca la respuesta del backend al tipo Post
      del frontend, rellenando con defaults lo que falte, o
  (b) ajustar el tipo Post y los componentes para tolerar esos campos como
      opcionales / cargarlos por separado (ej. comments vía lazy-load al abrir
      el post con GET /feed/posts/:id/comments en vez de venir precargados).

CAMBIOS QUE HABRÍA QUE HACER (cuando el usuario decida avanzar):
1. En FeedPage.tsx y FreeList.tsx: quitar `import { mockPosts }` y reemplazar por
